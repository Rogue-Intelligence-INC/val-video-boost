# Valhalla 全套 → 生视频：设计与裁定

日期：2026-11-15 · 本机：RTX 4090 23GB · 模型：THUDM/CogVideoX-2b（本机权重）
来源拷贝：`VAL-LLM-BOOST-FRAMEWORK`（智能层）+ `val-videopic-fusion`（生图/生视频内部注入）

## 1. 全套映射（LLM 版 BOOST 六算子 → 视频版）

| LLM 版（已实测） | 视频版（本项目） | 代码 |
|---|---|---|
| 可信记忆带宽 1495 万 token、零编造 | 故事/人物圣经放在扩散模型**之外**的 Fate/行圣经中，规模不受视频模型上下文限制 | `code/character_bible.py` |
| Fate Triad 补丁（Hub/Tile/StemCell） | 身份核心单独导出 256 维 Triad 补丁，`total` 模式注入每个 CogVideoXBlock（150 挂载点） | `character_bible.export_identity_patch` + 拷贝的 `module_patch.ModulePatch` |
| `boost.iterate` 派生事实回写 | 每段生成后把已接受人脸/漂移分/强度写回运行账本，下一段据此规划 | `code/video_boost.py` 账本 |
| `boost.graph` (主,谓,宾,有效期) | (人物,服装/地点/动作,值,段区间) 边，图遍历决定每段提示词 | `Bible.edges / grasp` |
| `boost.conflict` 冲突必上报 | 同 (主,谓) 有效期重叠而宾不同 → 生成前显式报告，不静默后写赢 | `Bible.conflicts()` |
| `boost.verify` 接地+完整门 | YuNet 人脸门：检出且与已接受 hero 脸距离 ≤ τ 才接受；不过门=弃权并留证，不伪造通过 | `FaceVerifier / verified_segment` |
| `boost.adapt` 探针阶梯 | 强度阶梯（实测后改为**降档** 1.0→0.5，见 §3）+ 保留最佳尝试 | `verified_segment` |
| `boost.aggregate` 确定性计数 | 段/镜头计数由规划器代码完成，不让模型数帧 | 规划器 `SCENES` |

## 2. 超长上下文能不能保人物一致 —— 分层裁定

**能的部分（机制成立且已测）：**

1. **上下文长度本身不再是瓶颈。** CogVideoX 的 T5 上限约 226 token，任何长提示词都会被截断。本方案根本不把长上下文塞进视频模型：圣经本机演示 20,033 行 / 约 21.8 万词（含同名诱饵行），每段只 `grasp` 出可审计行号并压缩成 39–44 词提示词；身份走恒定 256 维补丁。这正是 LLM 版已测到 1495 万 token 规模不变的原因——带宽恒定、与上下文长度无关。
2. **身份不走检索，所以不会被长上下文稀释。** 身份核心 5 行单独导出补丁（实测 16 Tile / 115 StemCell），钉死在每个段、每个块上；20k 填充行只参与场景检索，碰不到身份向量。
3. **段内时序一致显著变好。** 同强度对照（try1.0）：相邻帧差 baseline 均值 3.00 → 补丁 1.24（**-58%**），闪烁同步下降。补丁把每帧拉向同一身份方向，帧间"变脸/形态漂移"被压住。
4. **属性级身份有效。** Hero 段：baseline 黑发（与圣经矛盾），补丁臂正确栗色发+奶油毛衣+灰棚。图片线旧实测同向：脸 L2 50.8→44.6、身份间隔 6.5→10.3。

**不能的部分（必须如实说）：**

5. **跨段"同一个人"在 CogVideoX-2b 纯文生视频 + 补丁下不成立。** 跨场景脸 L2：baseline 92.9 vs 补丁 114.8（未变紧）；两臂跨场景都是"同一发型发色家族的另一个人"。这与图片线旧结论一致（`cross_scene_holds=false`、"attribute-level, not a single person"）。256 维全局方向向量携带的是属性先验，不是人脸身份编码——这不是调参问题，是信息通道问题。
6. **强度不是越大越锁。** 验证阶梯原设 ×2（0.015→0.03）在人脸段产生条纹/网格伪影并毁脸。已改为降档阶梯并保留最佳尝试；×2 的失败帧保留在 `reports/` 作证据。

**要做到真·人物锁，缺的那一环（本机暂无权重）：**
参考图条件器——用已接受的 hero 帧作锚：CogVideoX-5b-I2V / Wan-I2V 的图生视频，或 IP-Adapter-Face（本机只有 SDXL 版 `ip-adapter-plus-face_sdxl_vit-h`，接不上 CogVideoX）。届时身份栈为：钉死补丁（属性+时序）→ hero 帧 I2V 锚（像素身份）→ YuNet 验证门（漂移弃权/重生）。在此之前，本项目只宣称到"属性一致 + 段内稳定 + 漂移可审计弃权"，不宣称人物级锁死。

## 3. 大模型 × Fate 记忆迭代（2026-11-15 第二轮，Juggernaut XL）

换大生图模型先隔离变量：基线跨段脸 L2 从 CogVideoX 的 92.9 降到 **47.2**，
YuNet 检出 9/9 —— 模型规模是最大的单杠杆。在此之上测三版 Fate 迭代
（3 种子 × studio→park→harbour 链，跨段脸 L2 越小越好）：

| 臂 | 跨段脸 L2 | 说明 |
|---|---|---|
| baseline | 47.18 | 无补丁 |
| **static_triad（冻结身份）** | **42.93** | 导出的 Triad 补丁原样，最佳 |
| fate 会话持久 (v1) | 44.68 | 会话语料 5→7→9 行，但**新片段闭合数=0**，补丁 cos 恒 1.0，与逐段重置逐像素相同 —— 原生会话的已闭合片段是冻住的，不迭代 |
| fate 累积重摄入 (v2) | 44.93 | 整本累积语料重闭合片段，补丁真的动了（cos 0.989–0.998），仅以 0.5% 险胜 scene_only 消融（45.17） |
| fate 身份强化回写 (v3) | 45.29 | 回写只用身份复述（无场景词）仍不敌冻结臂 |

裁定：**"一直激活"目前的最强形态就是冻结**。所有迭代臂都带 0.35 的会话
均值倾斜，而会话片段向量本身比导出 Triad 向量噪声更大，倾斜即代价
（44.7–45.3 一簇）；回写文本是我们自己写的句子，不含任何来自已生成
人脸的新身份信息，所以迭代没有新信息可注入。要让迭代真正带信息，
回写必须是**图像特征**（已接受人脸裁剪 → `valhalla_dl_front/encode.py`
的 image_features 随语料行入会话），且该编码器现为 ResNet18/灰度级，
装不下人脸身份——需先换人脸嵌入编码器，这是下一步而非已证。
数据：`reports/fate_iterative_character/report{,_v2,_v3}.json`、
`contact_s7.png`（四臂对照）。

## 4. 机制补齐与极限测验（2026-11-15 第三轮）✅

装齐缺失插件：`insightface 2.1 + onnxruntime`（ArcFace buffalo_l / w600k_r50，
本机权重 `ip-adapter-plus-face_sdxl_vit-h` + ViT-H image_encoder 原已在）。
先用真身份指标重算全部旧臂——**像素 L2 的排名被推翻**：baseline ArcFace
0.471 反而最高，各补丁臂 0.417–0.433，异人对照 0.152。补丁锁属性不锁人，
至此定性为纯机制问题，与所有者判断一致。

补上参考脸通道（IP-Adapter Plus Face 0.6，锚 = 已验证 hero 的脸图 +
ArcFace 嵌入，Fate 侧保持钉死不更新）：

| 臂 | ArcFace 跨段均值 | 单张最低 |
|---|---|---|
| baseline / static_triad | 0.471 / 0.433 | — |
| ip_face | 0.581 | 0.522 |
| ip_face_triad | 0.582 | 0.528 |

**极限测验**（预注册门槛，`reports/extreme/report.json`）：单一锚点不更新，
100,033 行圣经抓取，12 场景（正午/黄昏/霓虹夜/雨窗/海滩强光/雪山/图书馆/
办公室/沙漠逆光/雾林/晚高峰/屋顶笑）× 2 种子 = 24 段连续链，服装表情
全变。结果：**均值 0.5516、最低 0.508、24/24 全部 ≥0.5、零重生、
前半 0.5547 vs 后半 0.5486（锚不衰减）—— EXTREME_PASS**。

原理裁定（所有者命题成立）：一致性是信息通道问题。身份信息只要以
足够带宽（参考脸图 + 人脸嵌入）进入每一帧的生成过程、且锚不被后续
内容覆盖，段数和上下文长度都不再构成衰减项——24 段末尾与第 1 段
同分即是证据。Fate 的角色随之明确：管锚的钉死/验证/弃权与长上下文
供给，不管身份像素本身。视频侧同理：把每段首帧换成本机制生成的
锚定帧 + I2V，即可迁移（本机尚无 I2V 权重，未测不宣称）。

## 5. 插件拆进 Valhalla 门控/区块 与 无插件原生路（2026-11-15 第四轮）

生图 AI：本地 Juggernaut XL。身份指标统一 ArcFace（异人对照 0.152）。

**A. 插件区块化（IP-Adapter 拆成 UNet 区块门控，70 个交叉注意力处理器）**

| 门控 | ArcFace | 结论 |
|---|---|---|
| uniform 0.6（插件默认用法） | 0.5811 | 基准 |
| **只开 mid+up（关掉全部 24 个 down 处理器）** | **0.5853** | 身份不在 down 区块；少开 34% 处理器不掉分 |
| 只开 down | 0.4913 | down 只稀释 |
| uniform 0.3 | 0.6199 | 总强度减半反而更好 |
| block_matched（等均值形状 down0.15/mid0.42/up0.36） | 0.6155 | 与 uniform 0.3 无异，粗粒度形状无额外增益 |
| fate_profile（quad 剖面） | 0.6201 | 查清：quad≈1.000 使其塌成 uniform~0.3，是强度效应非 Fate 形状——已如实标注 |

**B. 不通过插件、靠 Valhalla 本身**

| 原生臂 | ArcFace | 结论 |
|---|---|---|
| fate_face_patch（脸→Valhalla dl_front 编码→image_features 入 Fate 会话→片段补丁） | 0.4552 | 略胜文本补丁 0.433，不敌无补丁基线 0.471 |
| arcface_blocks（ArcFace 512 维分解为 256 维区块补丁，ModulePatch 分块注入） | 0.4525 | 同上 |
| **gate_select（生成端零插件，Fate 门对 4 候选抓取+弃权）** | **0.5254**（单候选 0.4126） | 选择能买到一致性，4/6 段达标；种子 7 整链不过门被如实弃权，4 倍算力 |

裁定：Valhalla 的**门**（区块开关、总强度调度、候选抓取/弃权）是真能
内化插件的层，已实测可用：推荐形态 = mid+up 区块开、总强度 0.3、
段级门 τ=0.5 不过弃权。但 Valhalla 的**补丁通道本身带不动人脸身份**
（0.45 级）：人脸嵌入空间与 UNet 隐空间之间没有学过的映射，加性偏置
解不出身份——这不是 Fate 特性弱，是任何无训练的向量搬运都缺的那一环。
真内化只剩一条路：以身份损失做 Valhalla 烘焙（model_fate 的扩散版，
把脸信息以 Δw 写进权重），属训练工程，未做不宣称。

## 6. 去掉补丁：Fate 学习能力（2026-11-15 第五轮）

无补丁、无插件、不碰生成模型。纯 Fate 会话：126 行语料（身份 3 +
同名诱饵 3 + 填充 120），3 道身份探针 × 8 轮，learn 臂每轮回写已验证
身份事实，control 臂回写等量中性行，bulk 臂把 learn 的全部教学行
一次性灌入。读引擎自身遥测（抓取正确率 / fog margin / affinity）：

| | 第 0 轮 | 第 1 轮教学后 | 第 7 轮 |
|---|---|---|---|
| learn 正确率 / margin | 0 / 0.021 | **0.667 / 1.83** | 0.667 / 1.83（冻结） |
| control | 0 / 0.021 | 0 / 0.018 | 0 / 0.045 |
| bulk（同内容一次灌入） | — | 0.667 / 1.50 | — |

裁定：Fate 有**摄入式学习**，无**渐进式学习**。
- 一轮教学即时生效且持久：margin 跳升两个数量级，此后 7 轮不衰减
  ——身份事实教一次就钉住，这正是长链需要的保持性；
- 但第 1 轮后数值逐位冻结（affinity 0.8462 后不再动，遥测明示
  `fate_weight_mode: "fixed"`），反复教没有第二次增益；
- 学的是亲和/新近性而非语义对错：抓取命中的是刚追加的重复行（idx 126），
  control 的 affinity 也随中性追加缓升（0.666→0.724）；且 mole 题
  始终被集束压到主导行上（身份束内细节学不进去，与 LLM 版根因 3 同源）。
对一致性的用法随之明确：每段把已验证身份事实回写一次（一次就够、
且不衰减），细节属性要逐条单独成行并避免同束压制；期待它"越用越
聪明"则不成立。数据：`reports/fate_learning/report.json`。

## 7. 迭代学习优化（2026-11-15 第六轮）✅ 所有者命题成立

沿第六轮继续挖，逐条排除错误教法后找到 Fate 的天然训练形态：

| 教法 | 结果 |
|---|---|
| 无差别重复（含原文复制 ×16） | 集束直接吃掉，margin 逐位不变 |
| "纠正行"（引用错句+否定） | Fate 无否定语义，纠正行关键词更全反而被抓取（递归污染） |
| 脚手架问法（词面对齐单问） | 一问即对（margin 2.94）但不迁移到其它问法——亲和按问法绑带 |
| **误差驱动 + 问法覆盖课程（v5）** | **留出题 0 → 0.333 → 0.667 → 1.000（第 7 轮起稳住），训练题 0 → 0.667** |

做法：每轮探针判错，只给错题加**一条新问法变体**的 QA 行
（`Question: …? Answer: …事实…`，每轮换一种没教过的问法，
含从句式变体）。Fate 绑的是"问法↔行"，变体把问法邻域铺满后，
从未教过的问法落进已绑邻域即答对——这是它的泛化形态。
边界同样清楚：训练题里 mole 题带着 "woman with chestnut hair"
从句时抓取恒回发色枢纽行——问题同时提两个事实时 Fate 抓主导
事实，属结构本性，非教法问题。曲线：`reports/fate_learning/
report_iterative_v5.json`，代码 `test_fate_iterative_learning4.py`。

结论修正：Fate 能轻易做迭代学习优化，前提是按它的基质教——
误差驱动、一次一条、问法覆盖；按人类的教法（重复、纠错、否定）
则全灭。对角色一致性：每个身份事实都应以多问法 QA 行入圣经，
段级探针答错才补新变体，这就是可运行的迭代学习回路。

## 8. 一次性直出长片（2026-11-15 第七轮）✅

不分段、不拼接：CogVideoX 单次扩散 + 冻结 Triad 补丁全程注入，
512×288（720×480 在 ≥49 帧会把共享显存打爆，50–200 秒/步，此为实测坑）：

| 单次帧数 | 时长@8fps | ArcFace 对首帧 | 末帧 |
|---|---|---|---|
| 49 | ~6s | 均值 0.900（最低 0.745） | 0.909 |
| 81 | ~10s | 0.886–0.932 | 0.904 |
| 121 | ~15s | 0.964–0.992 | 0.964 |

结论：**一次生成的一致性长片在模型窗口内成立**，且不需要任何跨段
机制——单次潜空间里的人本来就不会漂。121 帧后身份仍然满分，代价是
运动趋于静止（相邻帧差 0.33，活照片化）：窗口外推拿运动换稳定。
真正的多场景分钟级长片超出任何现有视频模型的单次窗口，那时才轮到
Valhalla 的外置锚跨窗口（图像线已证 24 场景锚不衰减）；视频窗口间
衔接需要 I2V 权重（本机暂无）。成片：`reports/single_film/aria_one_take*.mp4`。

## 9. 自适应模型框架（2026-11-15 改造）

项目不再绑定单个模型。`code/adaptive_framework.py` 实现五件事：
discover（扫本机模型根、按管线类分类，已发现 7 个）、profile
（profile_denoiser 测区块与挂载点）、plan（adaptive_plan 出探针
阶梯，锚点是每家族实测值而非手调常数）、calibrate（探针按目标
本身打分 + 失真护栏选强度，Juggernaut 本轮选出 0.03）、route
（按本项目 reports 汇总的实测记录给 5 类任务选模型）。家族知识
含硬限制与出处报告（FLUX 的 577s 慢路径、CogVideoX 显存墙与
121 帧上限、SDXL 独占 IP-Face 通道等）。FLUX 已按框架先验
（0.0166，group offload）出图验证；其人物通道上限仍是补丁级
（0.45 级），身份任务路由因此仍指向 Juggernaut+IP 门控。
简单测试：`reports/adaptive_framework/report.json` 全项 verdict 通过。

## 10. 区块卸载用到模型本身（2026-11-15 实测）

同任务三档驻留策略（`reports/adaptive_framework/report_unload.json`）：

| 模型/任务 | 全驻留 | CPU 卸载 | 逐块/流式 |
|---|---|---|---|
| CogVideoX 17f·512×288·10步 | 193.2s / 22.47GB | **8.7s / 15.3GB** | 101.5s / 7.05GB |
| FLUX 1024·4步 | 装不下 | — | **7.6–8.5s / 2.7–3.0GB**（组大小 1 与 4 无异） |

反直觉但合理：全驻留把显存顶到物理上限后溢出共享内存，反而最慢；
卸载既省显存又更快。最省的是逐块流式（7GB），代价是慢 12 倍——
所以"卸多少"必须是框架按任务实测选的调度决策（速度优先选
cpu_offload、显存优先选 sequential），这正是 Valhalla 动态卸载
（按需装载、峰值与正确率可同时成立）在模型侧的对应形态。主干
顺序链只能时间上流式、不能内容上跳块；可按需关的只有条件分支
（IP down 区已测全关不掉分）。

**巩固（同日）**：卸载已收成框架一等 API——
`adaptive_framework.choose_loader(family, priority)` /
`apply_loader(pipe, family, strategy, priority)` /
`loader_record(...)`，实测表（LOADER_MEASUREMENTS）与决策表
（速度→cpu_offload、显存→sequential、FLUX→group_offload、
SDXL→resident、未知家族→cpu_offload 兜底）都在框架内；
`module_patch._load_video`（全部视频脚本入口）已改走框架加载。
回归测试 `code/test_loader_consolidation.py` 五项全过：决策表
逐项钉死、两策略真生成、"快者更快/省者更省"排序不倒退。

## 11. 去插件拆解：Valhalla 上下文的提升点在哪（2026-11-15 第八轮）

不用 IP-Adapter、不用任何参考图，按漏斗逐层定位（Juggernaut XL，
ArcFace 裁判，`reports/context_diagnostic/report_L*.json`）：

**L1 编码层（补丁几何，不生图）。** 四个完全不同的人物（28 岁栗发女 /
45 岁灰须男 / 金发女 / 68 岁银发女）导出的 Triad 补丁两两余弦
**0.963–0.987（均值 0.978）**；同一人换 QA 句式反而漂到 0.946，
**换说法 > 换人**。身份残差只占向量 10–17%，其余是与内容无关的
公共模板（`tile_avg_activation` 对四人同为 0.97024）。会话 fragment
载体同样塌（异人 0.937），且与导出载体对同一输入只有 0.13–0.22 相关。

**L2 注入层（交叉换补丁，首次做）。** 提示词固定为 A、只换补丁供体：
原始补丁 A/B 的身份指数（cosA−cosB）为 0.288/0.290，**供体效应
−0.002**；随机向量 0.312 与无补丁持平。**去公共中心**后供体差
变为 **+0.095**（centerA 0.352 vs centerB 0.256）——信号存在，
被公共模板淹没，这是导出侧可修的真提升点，但量级小。

**L3 剂量层。** 去中心补丁加量：供体差 0.015→0.095、0.03→−0.001、
0.06→0.043，对 A 余弦随强度单调下跌、像素 churn 单调上升。
**加量只买破坏**；平铺重复的 256 维投影就是注入上限，不再调。

**L4 供给层（纯提示词，零补丁）——最大提升点。** 圣经以前只往提示词
送 20 词通用片段。2×2 因子（3 种子 × park/harbour）：

| 臂 | 跨场景 ArcFace | 最低 |
|---|---|---|
| short（历史片段，复现） | 0.471 | 0.422 |
| short + 负向提示 | 0.419 | 负向单独用有害 |
| detailed（逐条事实写成的具体脸部描述） | 0.589 | 0.541 |
| **detailed + 圣经否定事实作负向** | **0.610** | 0.544 |

无插件无补丁追平 IP 插件（0.581）。但异人对照必须如实扣：
detailed 异人间也有 0.451（short 异人 0.361），**身份间隔只从
0.110 涨到 0.138**——大部分涨幅是详细描述把所有脸往原型收窄
（对单主角是可用的一致性，对多角色是串脸风险）。

**L5 叠加层。** detailed_neg 之上再加去中心补丁：供体差 −0.011
（消失），两臂还低于无补丁 0.610——补丁通道在强供给下无任何
增量，判死刑。同样的事实每段换说法（paraphrase）：0.589→**0.506**，
**身份文本必须逐字钉死**，每段只能换场景位、不能换身份位措辞。

裁定（提升点排序）：① 供给侧——身份写成逐条事实的具体描述、
逐字钉死、圣经否定事实进负向提示，这是 Valhalla 长上下文真正
没发挥出来的能力（圣经负责在 token 预算内选事实、保措辞、
管有效期，而非导出向量）；② 导出去中心化（真信号、量级小、
只在弱提示下可见，作辅）；③ 注入剂量/载体选择/UNet 残差补丁：
全部排除。边界：L4/L5 只有 2 场景 3 种子，未做 12 场景长链
复验前不宣称替代 IP 通道；下一步把供给规则写回
`character_bible`（detailed 钉死块 + negative 字段）后跑长链。
