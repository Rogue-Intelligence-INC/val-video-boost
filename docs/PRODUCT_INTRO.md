# 产品介绍：Valhalla Fate 一致性控制层

**一句话：让 AI 短剧/影像里的同一个人，跨任意多场景、任意长篇幅，还是同一个人——
不用参考图插件，不绑任何生成模型，每一帧都有分数可查、不过线就自动弃权。**

隶属：Rogue Intelligence · Valhalla Boost 家族 · 状态：已实测验证的原型（2026-11-15）

---

## 1. 痛点

AI 生成影像最大的生产损耗不是“生成不出来”，而是**漂**：

- 同一个角色换个场景就换张脸，段与段之间是“同发型的另一个人”；
- 制作方只能肉眼验收、反复重抽（行业称“抽卡”），损耗无法度量、无法审计；
- 主流平台（Runway 参考图、Google Ingredients、Kling Elements、Vidu 主体库）
  的解法是把参考脸灌进**自家模型**——换模型即换工作流，角色资产不可迁移，
  素材必须上云，且依然没有质量判定：漂没漂，全凭人眼。

## 2. 解决方案

Fate 一致性控制层**不生产像素，负责让像素不漂**。它位于任何生成模型之上，
由 Valhalla 的人物圣经（Character Bible）与四个小接口组成：

```
人物圣经（模型之外的结构化角色资产）
  身份逐条事实 · 逐字钉死的身份块 · 否定事实 · 有效期服装表 · 冲突检查
        │ supply        每段把同一块身份文本原样送进生成（带指纹，可审计）
        ▼
任意生成模型 ×K 候选    Juggernaut / FLUX / CogVideoX……框架按实测自动路由
        │ enroll_face   第一段审定的脸登记为锚，只登记一次，永不更新
        ▼
Fate 选择 + 验证门      按锚选出最像的候选；低于 τ=0.5 自动弃权重生，
                        绝不静默交付漂移帧；每个候选的分数全量留痕
```

核心机制发现（均为本机实测，非推测）：一致性不由模型大小决定
（Juggernaut 0.471 vs 12B 级 FLUX 0.480），而由**每帧生成时身份
信息的在场方式**决定——逐字钉死的详细文本供给负责把候选分布
拉到角色附近，锚定选择负责从分布里挑出最像的，验证门负责守住下限。

## 3. 实测成绩（同一裁判 ArcFace，同人门槛 0.5）

| 指标 | 结果 | 对照 |
|---|---|---|
| 跨场景一致性（供给+选择） | **0.657**，最低 0.603，6/6 过门 | IP-Adapter 参考脸插件同台 **0.581** |
| 24 段长链（12 种光线/服装/表情） | **均值 0.630，最低 0.545，24/24 过线，零弃权** | 插件极限测验同门槛 0.552 / 0.508 |
| 48 段压力链 | 四等分 0.62/0.64/0.61/0.63，**无衰减**，最低 0.524 | 机制上时长由预算而非漂移决定 |
| 双角色交替出场 | 两人身份间隔 0.27 / 0.26，交叉低于门槛 | 双人同框（压缩供给）归属 2/3，持续优化中 |
| 剧情变老换锚 | 45 岁版新锚 4 场景 0.685，最低 0.655 | 有效期机制：身份只在剧情点换版 |
| 视频单 take / 跨窗口 | 窗口内 0.90；I2V 以锚帧续窗 **0.633** | 纯文生视频跨窗口只有 0.258（已证伪并绕行） |
| 交付下限保障 | 每段分数留痕，不过 τ 自动弃权 | 竞品无此项：肉眼验收、损耗不计 |

## 4. 与竞品的差异

| | 平台型（Runway/Vidu/Flow 等） | Fate 控制层 |
|---|---|---|
| 定位 | 生成模型 + 参考图功能 | **生成之上的控制层**，可挂任何模型（含竞品 API 的输出） |
| 角色资产 | 几张参考图，人肉维护 | 结构化圣经：事实、否定、有效期、冲突、多问法 |
| 质量判定 | 无，出图后肉眼看 | 每段 ArcFace 分数 + 身份指纹 + 弃权记录 |
| 模型绑定 | 死绑自家模型与云 | 模型无关，本地可跑（出图 ~2.5 秒/张，边际成本近电费） |
| 数据 | 素材上云 | 全程本地，适合未公开 IP 与隐私素材 |

## 5. 适用场景

- **AI 短剧/漫剧制作**：多集多场景主角锁定，弃权率即重抽成本，可预算、可审计；
- **虚拟角色/品牌代言人**：角色资产一次建立，跨 campaign 复用，换模型不换脸；
- **长篇叙事预演（previz）**：编剧侧的人物圣经直接驱动生成，服装/年龄按集生效；
- **生成管线质检（QC）**：已有 Kling/Runway 工作流的团队，外挂本层做选择与验收。

## 6. 当前边界（如实标注）

- 指定**外来真脸**（真人照片定妆）仍需参考图通道——本层会自动识别并弃权，
  路由层会将其指向参考机制，不假装能做；
- 双人同框已可用但间隔薄；分钟级多窗口视频全链、与商业平台的同台对标为下一阶段；
- 本产品为已验证原型，尚未服务化（API/界面在路线图上）。

## 7. 运行方式

```powershell
cd code
python run_pipeline.py                                  # 一条命令跑完整条链
python run_pipeline.py --scenes park,harbour,library --seeds 7,8 --k 4
python run_pipeline.py --hero <hero.png>                # 指定同源锚脸
python test_fate_consolidation.py                       # 16 项回归，随时验真
```

每次运行产出 `manifest.json`：路由决策、锚、每段全部候选分数、
选中帧、ACCEPTED/ABSTAINED 状态与身份指纹——交付的是可审计的成片链，
不是一堆无法复现的图。

## 8. 路线图

1. 多窗口视频全链（I2V 接缝法连 4+ 窗口）与同框复合选择；
2. FateInterface 服务化（REST/SDK）：任意生成器的外挂质检，按验收分钟计价；
3. 角色包格式导出（圣经 + 锚 + 有效期表），跨项目/跨模型迁移；
4. 与商业平台同协议对标，持续以实测刷新本页数字。
