# 智能缺口分析：为什么当前 Valhalla 只增强记忆、不增强智力

日期：2026-11-14 · 状态：本地立项分析（未推送）
上游：`val-llm-fusion-framework`（valhalla-server，commit af47f89）§13 实测

## 1. 现象（全部本机实测，不是推测）

作为 LLM 增强层（直连引擎+进程内 hybrid，不经网关），当前画像：

- 规模/保真：45 万→1495 万 token 三档均 17/21、逐题画像一致、编造 0；
  缺失弃权 4/4、注入抵抗 1/1、时序版本 1/1（胜同 top-8 检索的裸 RAG）；
- 推理探针：多跳 0/2、计数/列举 0/2（裸 RAG 反而 2/2）、矛盾静默选后写；
- 比较/合成/否定与裸 RAG 打平——那部分是解码头（Mistral-24B）本事；
- Fate 原生独白仅 4/12：结构层不会自己说话，它是门和骨架，不是脑。

结论先行：系统把"可信记忆带宽"拉满了，但没有给 LLM 增加任何
组合推理能力。下面是为什么。

## 2. 根因：九个机制坐标

1. **流水线只有一趟**：定向选行→Fate 门→解码头看 ≤4 行证据说一句话。
   没有中间结果、没有第二趟检索，组合推理在结构上无处发生。
2. **检索是问句锚定的单趟亲和**：多跳第二跳的桥接实体（Helix Cells、
   Halvorsen）根本不在问句里，词法/结构亲和≈0，证据永远进不来。
3. **集束与枚举互斥**：证据集束（Jaccard 同束留一）把"X 项目维护
   信标"这类近同模板行束成一条代表，计数/列举被自己的优化吃掉。
4. **Fate 门只判接地、不判完整**：裁决是"有没有一条可答的接地行"
   （margin vs δ/(dim+r)），不检查推理链是否闭合；无验证器、无自洽投票。
5. **派生事实不回写**：中间结论不进会话语料，跨题零积累；
   会话只长原始行，不长"已推出来的事实"。
6. **没有关系语义**：存的是文本行+相似拓扑（距离/共现成束）。
   相似≠蕴含；多跳、时序、冲突需要显式 (主, 谓, 宾, 有效期) 边。
7. **冲突无通道**：同一 (主,谓) 多个宾语时无有效期/取代边，
   检索近因决定答案（HAL-2 后写赢），系统不报告矛盾存在。
8. **运行时权重不学习**：§11.6 已审 `fate_weight_mode:"fixed"`；
   烘焙（model_fate Δw）的信号是结构亲和，从未拿推理对错当训练信号。
9. **智力本体在解码头**：内部 MCQ 阶梯实测 0.5B 65.2%→3B 97.8%
   （valhalla-transformer），结构与之正交；换头即涨分，结构不涨。

一句话：当前架构是"记忆外设"，不是"推理协处理器"。它优化的是
**证据的供给与纪律**，从未触碰**证据之上的运算**。

## 3. 参考项目：别人用什么机制补"智力"

内部先例（本机工件）：

- unified-core `multihop_fate/v2` 专用解码：MultiHop-RAG 切片
  15/25（v1 为 9/25）——按题型（entity/yesno/relation）走专用抽取
  路径确实有效，但走引擎原生路径、我们的 hybrid 没触发，且 yes/no
  占比高、错答呈猜测形态，是窄模式解码不是通用推理；
- MCQ 阶梯与 model_scaling：智力随解码头规模缩放，Valhalla patch
  只平移先验——"增智"最可靠的杠杆仍是头本身+任务信号训练；
- 孵化集束/场强/逃逸：是压缩与抓取机制（连接 1986 万→4.2 万），
  本质是记忆组织，不是推理（且与枚举互斥，见根因 3）；
- fate_longchain：长链锚点保持 66.7%——是保持，不是推理增益。

外部同构路线（机制对照，非本机复现）：

| 项目/路线 | 补的机制 | 对应我们的缺口 |
|---|---|---|
| HippoRAG（KG+Personalized PageRank） | 图上扩散激活做多跳召回 | 根因 2（多跳） |
| Microsoft GraphRAG | 实体图+社区摘要 | 根因 3（聚合/全局题） |
| LightRAG | 图+向量双层检索 | 根因 2/6 |
| Zep/Graphiti | 双时序边（valid/transaction time） | 根因 7（冲突/时序） |
| Self-RAG / CRAG / ITER-RETGEN | 迭代检索+自我批评+再检索 | 根因 1/2/4 |
| ReAct / Reflexion / Tree-of-Thoughts | 测试时搜索/反思循环 | 根因 1/5 |
| MemGPT/Letta | 显式工作记忆分层 | 根因 5（但无正确性门） |
| DSPy | 以指标优化提示/模块程序 | 根因 8（系统化调参） |

共同点：**智力增益全部来自"证据之上的运算结构"**——图遍历、迭代、
聚合算子、时序边、验证循环——没有一家靠"把检索做得更准"得到多跳。

## 4. 裁定：按理说能不能增强智力

能，但有条件——"增强智力"必须定义为：**在固定解码头下，让系统
完成单趟检索+一次解码完不成的组合任务**（多跳、聚合、时序推理、
冲突识别、跨题积累）。达成路径只有三类，缺一不可：

1. **运算结构**：迭代检索（派生事实回写再检索）、关系图遍历、
   确定性聚合算子（计数/求和不许 LLM 心算）、冲突/时序通道；
2. **验证闭环**：答案对证据集的蕴含校验+不完整则继续检索或弃权
   ——把 Fate 门从"判接地"升级为"判接地且判推理完整"；
3. **训练信号**：QA 对错回流 Fate 权重/烘焙（离线），让结构先验
   朝任务正确率移动，而不是只朝亲和收敛移动。

仅做检索优化（现状）永远到不了——这不是调参问题，是流水线
缺少"运算"这一级。

## 5. 本框架（VAL-LLM-BOOST-FRAMEWORK）拟补的模块

建在 val-llm-fusion-framework 之上，不动已测的记忆层：

- `boost.iterate`：问题分解→检索→派生事实（带出处行号）回写
  scratch 会话→再检索，最多 H 跳；终点仍过 Fate 门；
- `boost.graph`：摄入时抽 (主,谓,宾,有效期,来源行) 边，与文本行
  双写；多跳走图遍历，文本行作证据回呈；
- `boost.aggregate`：枚举/计数题型识别→豁免集束→谓词全集扫描+
  确定性计数，LLM 只负责 verbalize 结果；
- `boost.conflict`：同 (主,谓) 多宾并存时显式上报冲突+按有效期
  给出当前值，不再静默后写赢；
- `boost.verify`：答案蕴含校验（证据集 vs 答案断言逐条对齐）、
  自洽采样分歧时降级为弃权或续检索；
- `boost.adapt`（离线）：QA 对错日志→Fate 权重阶梯/烘焙 v2，
  以推理题集回归为准入门。

验收门（先立尺、后动手）：多跳探针 ≥1/2 起步、聚合 2/2、冲突
必上报、时序保持 1/1；且极端三档 12/12、编造 0、多模 9/9 不回归。

## 6. 孵化仓权重处理复核（2026-11-14 追加）：能否迁移成增智

孵化仓（valhalla-self-incubate + Valhalla/manifestsys）有三层"权重"，
性质完全不同：

| 层 | 机制（代码坐标） | 学的是什么 |
|---|---|---|
| Tile 边权 | 出生 0.1（双端激活高于全体均值才连，每轮≤1 条）；Hebbian 更新 Δw = a_i·a_j·0.01、钳 [-1,1]（tile_complete.rs:1293-1301）；加权和进 tanh 激活 | 共激活统计——真在线可塑性 |
| Stem 连接强度 | 每周期按高维距离整体重写：最大相对间隙截断邻居、集束只留束内场强最高者、高能逃逸边；强度=目标场强=能量·√复杂度（stemcell_complete.rs:1114,1289-1373） | 几何相似的派生态——重算，不是经验学习 |
| Fate/LLM 权重 | Fate 权重阶梯（离线）；model_fate 烘焙 Δw 进检查点 | 先验平移——信号是结构亲和、非任务对错 |

实测成色（records/sprout-cycles.md）：权重确实被改（sprout-8：1590 条
边 1059 条被激活改过），但活网络最大可达块只有 7–11 个 Tile、Stem
大块纯度 0.02–0.03（英文小说与算术夹杂）——学到的图稀疏、碎片、
语义不纯；且 DESIGN.md 明示只喂料不传播时边数恒 0。

**能否增智——裁定**：

- **直接不能**：三层权重都不含推理算子，改变的是"谁与谁相连、
  谁被抓取"，即路由与巩固（类睡眠整理），不是组合/计数/校验。
  我们线上 QA 路径甚至没调用 Tile `propagate`——权重练了也没在
  答题时用上。
- **有一条真路（机制现成）**：查询时**激活扩散**。第一跳事实激活
  其 Tile 后，沿 Hebbian 边权加权传播即可达第二跳——这正是
  HippoRAG 在知识图上做 PageRank 扩散的同构机制，可把多跳从
  "词法命中"变成"图上可达"。缺口在接线与纪律：传播轮数/停机、
  终点 Fate 复核、高频≠真实（注入行被共激活也会被强化，
  Fate 门必须仍是权威）。
- **烘焙路不算增智证据**：孵化权重可作离线训练信号（QA 反馈
  阶梯已有雏形），但"图权重→LLM 权重→推理变强"无闭环实测，
  按未证处理。

对 BOOST 的修正：`boost.iterate` 第二跳优先复用 Tile 传播+
Hebbian 边权（仓内现成），不必先建外部 KG；但须先解决活网络
碎片化（最大块 7–11）——传播半径不够时多跳仍到不了。建议先测
一条：共摄入桥接事实对 → 孵化 N 周期 → 查询时开 2 轮传播，
看第二跳可达率。

## 7. 简化适配实测（2026-11-14）：三算子接上增强层

把 §6 的机制简化为三个算子，在 valhalla-server 增强形态上实测
（脚本 `tests/run_boost_adapt.py`，同一 100,006 行/~149 万 token
语料、同一 22 题、同一解码头；基线 hybrid 17/21、裸 RAG 14/21）：

- **spread**：查询时激活扩散——第一跳证据抽桥接实体→第二趟检索；
- **aggregate**：确定性计数/列举算子（稀有 token 谓词全集扫描、
  代码计数、豁免集束），带意图门（只认枚举型问法）；
- **纪律**：扩散证据先过注入隔离；空答回落显式弃权。

| 臂 | 总分 | 多跳 | 聚合 | 注入 | 缺失 | 释义 |
|---|---|---|---|---|---|---|
| hybrid（基线） | 17/21 | 0/2 | 0/2 | 1/1 | 4/4 | 2/2 |
| boost v1（算子裸接） | 13/21 | 1/2 | 2/2 | 0/1 | 2/4 | 0/2 |
| boost_hybrid（扩散喂生产路径） | 17/21 | 0/2 | 0/2 | 1/1 | 4/4 | 2/2 |
| **boost v2/v3/v4（算子+纪律）** | **20/21** | 1/2 | 2/2 | 1/1 | 4/4 | 2/2 |

三个机制结论（都有失败工件）：

1. **算子有效，但裸接有害**：v1 多跳/聚合当场见效，却被扩散带入
   的注入行毒翻（AUR-999 全面开花）、算子误火属性型 "how many"
   题——召回变宽=毒面变大，必须先有纪律再有扩散；
2. **生产 hybrid 路径会把增益过滤掉**：boost_hybrid 里扩散已把
   双跳行喂进会话，`hybrid.resolve` 的集束+证据上限又束回 0/2
   ——集成点必须在 resolve 内部（枚举豁免+算子证据直通），
   不是喂料口；
3. **剩余天花板是实体消歧**：hop_employer 三版未过——桥接人名
   在 10 万行填充里同名 ~90 行，v4 实体锚定后失败模式已从
   "猜错实体"变为"证据不足弃权"（更安全），但简化机制到此
   为止；再往上需要真图遍历/引擎 multihop 专用解码（步骤 1/5）。

附带观察（未评分）：冲突题在扩散证据下答出 "HAL-1 and HAL-2"
——双行同呈时解码头会自发并列，冲突上报通道（boost.conflict）
可能只需"同谓词多宾证据强制同呈+标注"，成本比预想低。

数据：`valhalla-server/tests/results_extreme/boost_adapt_lines100006.json`，
日志 `tests/boost_adapt{,2,3,4}.log`。本仓仍未推送。

## 8. 待办（2026-11-14 定版）：引擎 fate_grasp 场序出口

审计确认：抓取的忠实实现不在 Python 层。引擎的场是信号空间的
（亲和×信号余弦、场强=能量·√复杂度、margin=信噪判据），HTTP
只给 top-1 行号，逐行场值没有出口，网关只能在文本空间猜场。
当日实验：Python 层 Fate-only 三版把基线从 12/12 弄到 8–10/12，
已回滚多轨基线（valhalla-server ebe8c36），复现 OVERALL PASS。

正解（排期单独做）：Rust row 增加 `fate_grasp` 出口——按引擎挑
top-1 的同一套结构分给出 top-k (idx, score)，hybrid 证据改按
场序取行、transformer 只口头化；弱放行门保留物理 margin；
"重抓"改为信号再脉冲（多周期/反馈调亲和），不再用文本改述。
验收：极端三档 ≥12/12、多模 ≥9/9、增强 ≥17/21 且证据来源
100% 为 fate_grasp 行（可审计）。

**进展（2026-11-14 晚）**：`fate_grasp` 出口已落地并部署
（`rust/fate_qa.rs`、candidate 序列+激活区块+抓取行），只暴露
读数、行为零变化；seg 编号连续与 fragment 窗口卸载一并完成
（会话线 46MB→1.49MB）。离线校准结论：相对 margin 在极端集
可分、affinity 是反馈记忆不可当门、多模 q1 与 premise/swap
序列判不了——详见 `docs/FATE_SILENCE_AND_UNLOAD_ANALYSIS_20261114.md`，
原版设计规范见 `docs/ORIGINAL_FATE_DESIGN.md`。待续：
candidate_indices、首段收口、区块内序列复验后才换门。
